# Отложенное применение мер

Функция добавляет долговечную цепочку: предупреждение → льготный срок → повторная проверка → выбранное действие. Она выключена по умолчанию и после обновления начинает работу только после явного включения в **Настройки → Применение мер**.

## Безопасный запуск

1. Оставьте режим `dry_run` и добавьте тестовые UUID в пилотный список.
2. Используйте «Смоделировать», чтобы проверить подходящее нарушение и снимок политики.
3. Переключитесь на `deliver_only`: предупреждения будут отправляться через существующие шаблоны нарушений, но итоговое действие останется только в журнале.
4. Для автоматической меры выберите `enforce`, тип нарушения, минимальный score, действие и срок. Для `throttle` отдельно задаются скорость и длительность. Пустой пилотный список означает всех подходящих пользователей.

Снимок политики сохраняется в каждом кейсе, поэтому изменение настроек не меняет уже начатый срок. Перед действием система заново проверяет нарушение, пользователя и whitelist. Дедлайн и состояние хранятся в PostgreSQL и переживают перезапуск.

## Поддержка

При включённой паузе обращение переводит активный кейс в `paused_for_support`. Для внешнего бота или Helpdesk включите Public API (`EXTERNAL_API_ENABLED=true`), создайте API-ключ только с областью `enforcement:support` и отправьте идемпотентное событие:

```http
POST /api/v3/enforcement/support-events
X-API-Key: rwa_...
Idempotency-Key: message-123
Content-Type: application/json

{
  "event": "customer_contacted",
  "user": {"uuid": "00000000-0000-0000-0000-000000000000"},
  "ticket": {
    "provider": "generic-helpdesk",
    "external_id": "ticket-123",
    "url": "https://support.example.com/tickets/123"
  }
}
```

Разрешены также `telegram_id`, `email` и `username`. Мера приостанавливается только при одном однозначном совпадении; текст переписки не нужен. Повтор с тем же `provider` и `Idempotency-Key` не создаёт новых действий.

## Действия оператора

Очередь показывает статус, дедлайн, режим и решение. «Выполнить сейчас», перевод на ручное рассмотрение и отмена требуют права разрешения нарушений и записываются в аудит.
