# Участие в проекте

## Issues

Ошибки и предложения — в [issues](https://github.com/Case211/remnawave-admin/issues). Что полезно приложить к сообщению об ошибке:

- версию панели (карточка на дашборде) и версию агента, если дело в ноде
- кусок логов вокруг проблемы
- что уже пробовали

## Pull request

```bash
git checkout -b feature/название
# правки
git commit
git push origin feature/название
```

Дальше — pull request в репозиторий. Полезно, чтобы изменение приезжало с тестом: он заодно объясняет, что именно чинилось.

При первом pull request бот попросит подписать [CLA](https://github.com/Case211/remnawave-admin/blob/main/CLA.md) — это одна строка комментарием, дальше подпись запомнится.

## Правки документации

У каждой страницы внизу есть ссылка «Предложить правку» — она открывает файл сразу в редакторе GitHub. Исходники лежат в `docs/`, сайт собирается VitePress и публикуется автоматически при пуше в `main`.

Русская версия — в корне `docs/`, английская — в `docs/en/`. Если правите текст, который есть в обеих, поправьте обе: расходящиеся переводы хуже отсутствующих.
